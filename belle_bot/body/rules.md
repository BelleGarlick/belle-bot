# Rules
Here are some small rules to follow whilst contributing.

### Rule 1: Have fun!
This is a happy funtime project. You should be happy and having a fun time with it. If you are not, take a break!!!


### Rule 2: If you use AI say so
This is a learning project. If you use AI you should state as such with a comment around / under your AI generated code and state the following:
1. What is the code doing
2. Why you used AI here
3. What sources were you able to find on the subject matter after the AI helped you. 
4. (optional) which AI you used

This is not to shame or discourage you from using AI. This is to enforce ownership over code and force critical thinking instead of mindlessly vibe coding. Whilst this is a hobby project it's main purpose is to help eduate and show how to get better at a skill. Have a real go at solving a problem first before jumping straight to the answer, and try to learn something once you have the answer. 



### Rule 3: Clean commits.
Commits should have the following types:
- DOC: Update to documentation
- CHORE: A menial change such as renaming a variable
- FEAT: A new piece of work such as adding in a new module
- TEST: Adding in tests
- BUGFIX: A fix to a bug 
- REVERT: Go back on a change
- REFACTOR: Moving code around to be cleaner or performance better


### Rule 4: Clean code base:
1. Modulate things where possible into their individual hardware componts. If you want to run a motor, create a module for it and put the code in there to top it building up in the main loop. 
2. Keep functions to the NASA standard of under 50 lines of code to minimize the changes for bugs.
3. Ensure types are give explicitly when declaring variables.
